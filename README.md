# pages-workflows

Shared GitHub Actions workflow for **pages.lifesci.ucla.edu**. Site repositories call it; they never contain deploy logic of their own.

## What it does

1. Runs only for a push (or manual run) on `main`, on the LSC on-prem runner (label `lsc-pages`).
2. Builds the site in a throwaway Podman container (`node:22` for Astro, a Hugo image for Hugo, nothing for plain HTML).
3. Deploys with the site's own key, which can only write to that site's directory on the web nodes.

The site is identified by its repository name. The runner looks it up in its
site registry (`/etc/pages/sites.json`, generated by Ansible from
`group_vars/all/sites.yml`), which gives the path, generator, custom domain and
deploy key. A repository that is not registered is refused. For Astro, the
build sets `SITE_BASE=/<dept>/<site>` while the site lives under
pages.lifesci.ucla.edu, and no `SITE_BASE` once it has its own domain.

## Caller (identical in every site repository)

```yaml
name: Publish site
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
jobs:
  publish:
    uses: uclalifesciences/pages-workflows/.github/workflows/deploy.yml@v1
```

No inputs and no secrets. `workflow_dispatch` lets the pages console trigger a
rebuild. Older callers that pass `site`/`generator` inputs and a `DEPLOY_KEY`
secret still work.

## Organization setup (LSC, once)

Works on the GitHub **Free** plan:
- Create this repo as `uclalifesciences/pages-workflows`, **public** (no secrets in it), and tag a release `v1`.
- Site repositories are **private**. On Free, org-level secrets and variables are not visible to private repos, so nothing is stored at org level or in site repos: the deploy keys and the list of web nodes (`PAGES_HOSTS`) live on the runner, set by Ansible.
- On Free there is only the default runner group: keep its "Allow public repositories" option **off**, so only the org's private repos can use the on-prem runner.
- Org setting: require approval for workflows from outside collaborators/forks.

## Adding a site (LSC)

1. Add the site, with its `repo`, to `group_vars/all/sites.yml` in the Ansible project.
2. `scripts/new-site-key.sh <dept/site>`: creates the site's deploy key pair.
3. `ansible-playbook pages.yml -K`: authorizes the key on the web nodes and installs the registry and private key on the runner.
4. The site repository contains the caller above (the starter template already does).
